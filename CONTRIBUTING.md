# Contributing

Thank you for helping build AI in the Wild. Contributions are welcome from wildlife researchers, conservation teams, field engineers, data scientists, hardware builders, and open-source maintainers.

## Good First Contributions

- Improve a research theme with field knowledge.
- Add missing terminology to the glossary.
- Propose a project using `projects/project-template/`.
- Add hardware deployment notes.
- Improve JSON Schemas with real-world metadata needs.
- Fix broken links or unclear documentation.

## Contribution Principles

- Start from a research question, not from a model.
- Treat wildlife location, endangered species data, and sensitive field sites with care.
- Prefer reusable templates and schemas over one-off project notes.
- Keep code small until a workflow has been validated in a real project.
- Document assumptions, limitations, and field conditions.

## Project Proposals

Use the GitHub issue template or copy `projects/project-template/` when proposing a new project. A strong proposal should include:

- Species or taxonomic group.
- Site or region, with sensitivity level.
- Research question.
- Data sources and collection devices.
- Expected AI capability.
- Ethical, legal, and conservation risks.
- Field owner and technical owner.

## Pull Requests

Before opening a pull request:

- Confirm the change fits the repository scope.
- Link related issues or project proposals.
- Update relevant documentation.
- Validate any JSON files.
- Avoid adding large data files or model weights directly to the repository.
